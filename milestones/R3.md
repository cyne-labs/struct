## Part A: the doctor in `structl`

Add a `doctor` module with exactly this public surface:

- `doctor(schemas: &str, text: &str, options: &DoctorOptions) -> DoctorReport`;
- `DoctorOptions`:
  - `mode` is `Strict` or `Salvage` (default `Salvage`);
  - `retry_hint` is a bool (default `true`).
- `DoctorReport`:
  - `data`: an `Option<DecodedFile>`. It is `None` in strict mode when there's any bad line, or when nothing usable is left;
  - `text`: the repaired file in canonical form, matching `data`. It is empty when `data` is `None`;
  - `repairs`: a list of `Repair`. Each has its line, column, which of the 6 safe fixes it was, the original text and the new text;
  - `bad_lines`: a list of `BadLine`. Each has its line, column, a problem message, the original line text, and whether it was dropped as the child of another bad line;
  - `hint`: an `Option<String>`, present when `retry_hint` is on and there's at least one bad line.
- `splice(schemas: &str, original: &str, report: &DoctorReport, reply: &str, options: &DoctorOptions) -> Result<DoctorReport, StructError>`. It replaces the bad lines with the reply's lines, in order, then runs the doctor again. A reply with a different number of lines than there were bad lines (not counting dropped children) is an error.

Line and column numbers always refer to the model's original text.

**The hint format** is fixed. Write it exactly like this:

```
Some lines were invalid. Rewrite only these lines, one per line, in the same order:
1. <original line text>   (<problem>)
2. ...
```

Write the problems in a few plain words, such as `expected 5 columns, found 4` or `'refuetd' is not one of: supported, refuted`.

## Part B: synthetic tests (`cargo test --offline`)

1. **One test per safe fix (6 in all),** at least 3 cases each, checking the exact repaired text and the exact `Repair` entries.
2. **One test per kind of bad line,** checking that nothing is edited and the exact `BadLine`. Cover at least:
   - wrong column count, too few and too many;
   - an unescaped `|` inside text;
   - an enum typo;
   - a depth jump;
   - a missing index;
   - an unclosed raw value in the middle of the file;
   - `N/A` and `"quoted"` in a text field, which must be left alone;
   - `null`, `None`, `N/A` and `NaN`-style words in `int`, `bool` and `enum` fields, which must be reported, never turned into `~`;
   - `true`, `false`, `yes` and `no` in a `bool` field, which must be reported, never converted;
   - an empty field, `"2024"` in an int field, `+5`, `1,000`, `Supported` for the label `supported`, and `year: 2024`, all of which must be reported, never changed;
   - `3,14` in a float.
3. **Strict versus salvage** on the same input. In salvage, a dropped depth-0 line must take its child lines with it.
4. **Hint and splice:**
   - the exact hint text;
   - a correct reply spliced back in and producing clean data;
   - a reply with the wrong number of lines rejected;
   - a reply that is itself still bad, reported again.
5. **The damage suite, at least 5,000 cases.** Reuse the R2 random generator to make valid files, written with outside schemas, then damage each one in a known way:
   - **fixable damage:** one or more of the 6 safe-fixable mistakes. The doctor must give back *exactly* the original data, and report exactly the damage that was done;
   - **unfixable damage:** mistakes from the bad-line list. The doctor must report the damaged line and **must not change anything**. A changed value is a *false repair*;
   - **no damage:** the doctor must make zero repairs and report zero bad lines.

   Report the cases per kind of damage and the number of exact restorations. **False repairs must be 0**; any other number fails the milestone.

## Part C: real model output (after Part B passes)

This follows rule 7: check `nvidia-smi`, run one model at a time on `127.0.0.1:8090`, and stop the server afterwards. Write `bench/r3/collect.py` and `bench/r3/run_doctor.py`.

   - **Thinking text:** for thinking runs, cut off everything up to and including the model's end-of-thinking tag. Count those tokens separately. If the tag never appears, the run has no Struct output; count all of its tokens as thinking.
2. **Sandbox and back up.** Save every raw output, unchanged, as its own file in `bench/r3/real/raw/`. Copy that folder to `bench/r3/real/backup/`, and write `bench/r3/real/SHA256SUMS` with a hash for every file. Real outputs are **never** used in `cargo test` and never edited. The doctor runs on copies in memory.
3. **Run the doctor** in salvage mode on every output. Report:
   - per run: clean as written, fully repaired, salvaged (with how many bad lines), or nothing usable;

   - bad lines counted per problem;

4. Before finishing, check that every hash in `SHA256SUMS` still matches.
